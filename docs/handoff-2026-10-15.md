## The product in one paragraph

Lattice turns a topic into a narrated explainer video (about 90 to 120 seconds) for teachers and
YouTube creators. A cheap model (DeepSeek V4.1 Flash on OpenRouter, reasoning off) plans the
lesson; program code draws it in headless Chrome, voices it with Kokoro, and joins it with FFmpeg.
Code owns every number and every picture; the model owns the teaching and the words.

## What has been learned (measured, not guessed)

- One model call that designs the teaching, declares the data and picks every move fails more often
  than not, on a cheap model and on GPT-4.1 alike. Splitting the work is what worked.
- The staged planner for table lessons: the model describes the teaching and the table; code checks
  the description against itself, lists every case, builds every step; the model writes one
  sentence per step with the numbers in hand. Live: 5 of 5 table topics plan in 4 to 6 calls at
  under half a cent (binary strings, domino tilings, climbing stairs, steps of 1 to 3, coins).
- Independent AI reviews (a reviewer given the prompt, the plan and two frames per beat): the old
  single-call lessons scored 3.5 to 5 out of 10; the staged lessons 5 to 6. Best so far: climbing
  stairs at 6. What still holds lessons back: the naive attempt's cost is weakly felt, the check
  question is sometimes a lookup, and some sentences misdescribe the table's rule.
- Jev routing: 13 of 15 topics right against 6 for keyword matching. Its confidence runs low on
  right answers, so the cut-off is 0.30. As a sentence judge it catches about two thirds of wrong
  claims and most missing reasons, and wrongly flags 6 to 15% of good sentences, so it is soft.

## Known faults from the last reviews (binary strings and domino tilings, both 5 out of 10)

Code-listed cases made the splits honest, but the score did not move. What the reviewers found:

- The crux is never said: for binary strings, that a 1 cannot follow a 1; for dominoes, what V and
  H are. The narration step is not told what the split's reason is.
- Units read wrongly on the cost lines: "Cases for 19 strings", "Cases for 20 tilings". The prompt
  asks for a size word ("letters", "columns") but nothing checks it; the label could be built from
  the topic's own size word instead.
- Labels go stale: the list keeps its "length 4" heading over struck-through shorter cases; the
  table is labelled like the cases but holds counts.
- The check question is often a value already on the table, answered three seconds later.
- No picture of the real problem (no strip, no domino, no staircase).
- Possible bug: in one run the Jev rewrite produced a better sentence but the built lesson kept the
  first one. Check `generate` in `planner/lesson_recurrence.py`: the rewrite is accepted only if it
  passes the same shape checks in one attempt.

## Rules that bite

- **No patchwork.** Every fix is a general rule with a test that fails without it.
- **Before every commit:** `.venv/Scripts/python.exe -m pytest -q` and
  `.venv/Scripts/python.exe -m scripts.video_regression` (about 30 minutes; it includes a Manim case,
  so Docker Desktop must be running: `Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"`).
  Docker stops whenever the machine restarts.
- **Commits** carry the owner's name only: no Claude or AI trailer or attribution.
- **Judge by rendered frames**, not by how clean the plan looks. The scripts and the reviewer brief
  used so far are in `scripts/lesson_lab/`.
- **Live model calls cost money.** State a cap before a batch. OpenRouter and Jev keys are in `.env`
  (not in git; never print them). Git Bash `curl` fails on OpenRouter here; use Python.
- Work that might break the main folder goes in a git worktree on its own branch, merged only after
  tests and the regression pass. `../Franko-show` is a leftover worktree whose branches are merged;
  it can be removed with `git worktree remove ../Franko-show`.
- Reply to the owner in plain, short English.
